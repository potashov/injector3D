# Мениск при малом объёме и большом наклоне: разрыв и смешанный контакт

**Дата:** 7 ноября 2026
**Статус:** проблема локализована; реализован clipped-солвер со смешанной
линией контакта, интегрирован в `build_liquid()`. Итоги —
`reports/meniscus_mixed_prototype.md`.

## 1. Наблюдение

Запуск с малым объёмом и большим наклоном падал на проверке объёма:

```bash
$BL --background --python injector3d/create_scene.py -- 4.5 \
    --tilt-count 1 --tilt-angle 50 --volume-mm3 2000
```

Для наклонного меша получалось:

```text
level = 21.316 мм
V     = 2237.00 мм³   (цель 2000.00 мм³)
```

`validate_liquid()` завершался с расхождением около 12 %. Причина — не
ошибка бисекции как таковой, а **разрыв объёма** между двумя режимами
построения поверхности: плоским fallback и полным мениском.

## 2. Как сейчас строится мениск

Свободная поверхность жидкости горизонтальна в мире. Для полного
мениска:

1. задаётся уровень жидкости на оси `level`;
2. плоскость контакта со стенкой берётся на высоте
   `z_contact = level + rise`, где `rise ≈ 3.034 мм` — подъём жидкости
   у стенки;
3. предполагается, что эта плоскость пересекает **цилиндрическую
   стенку по замкнутому эллипсу**;
4. плоская крышка среза заменяется радиальной менисковой сеткой.

Это работает, только если плоскость контакта проходит выше **самой
высокой точки дна**:

```text
z_contact > z_bottom_max
```

Иначе плоскость задевает дно, и контактная линия уже не является
замкнутым эллипсом на стенке. В этом случае `_build_meniscus_bmesh()`
включает плоский fallback: горизонтальная поверхность на уровне `level`
без мениска.

## 3. Геометрия для 50°

Для наклона 50° и текущей точки опоры:

```text
rise          ≈  3.034 мм
z_bottom_max  ≈ 24.350 мм
level* = z_bottom_max - rise ≈ 21.316 мм
```

Здесь `level*` — граница, на которой плоскость контакта касается самой
высокой точки дна.

На этой границе два режима дают разные объёмы:

```text
level чуть ниже level*: плоская поверхность, V ≈ 1939.64 мм³
level чуть выше level*: полный мениск,       V ≈ 2241.39 мм³
```

Скачок:

```text
2241.39 - 1939.64 ≈ 301.75 мм³
```

То есть при переходе к полному мениску почти вся менисковая шапка
добавляется сразу, а не постепенно.

## 4. Почему цель 2000 мм³ не решается

Целевой объём попадает в интервал, недостижимый ни одним из двух
режимов текущей модели:

```text
V_flat(level*) ≈ 1939.64 < 2000 < 2241.39 ≈ V_meniscus(level*+ε)
```

Следствия:

- при `level <= level*` строится плоская поверхность; её максимальный
  объём на границе — 1939.64 мм³;
- при `level > level*` строится полный мениск; его минимальный объём на
  границе — около 2241.39 мм³;
- уровня, который дал бы ровно 2000 мм³ в рамках этих двух конструкций,
  нет.

`build_liquid()` использует бисекцию по `V(level)`. Бисекция
предполагает монотонную непрерывную функцию, а здесь функция имеет
разрыв. Поэтому она сходится к границе и возвращает один из краёв:
меш с объёмом ~1939 или ~2237–2241 мм³ вместо 2000 мм³.

## 5. Почему нельзя просто «правильно посчитать мениск»

Для 2000 мм³ при 50° нужен мениск со **смешанной линией контакта**:
часть контактной линии лежит на цилиндрической стенке, а часть — на
дне или внутренней галтели. Текущий генератор мениска умеет только
замкнутую эллиптическую кромку целиком на стенке.

Чтобы корректно построить такой меш, нужно:

- решать профиль мениска с граничными условиями на стенке и на дне;
- строить контактную линию, которая может состоять из участков разного
  типа;
- корректно обрабатывать переход топологии при изменении уровня;
- сохранять горизонтальность свободной поверхности в мире;
- обеспечивать manifold-меш и точный объём.

Это отдельная геометрическая задача, а не поправка уровня в текущей
радиальной схеме.

## 6. Текущий обход

В `build_liquid()` добавлено обнаружение разрыва. Если после обычного
решения фактический объём отличается от целевого больше допуска:

1. уровень пересчитывается по плоскому телу
   (`solve_level_for_volume(..., flat=True)`);
2. строится плоская поверхность с точным объёмом;
3. в `info` возвращается `flat=True`;
4. `contact_level_mm()` / `contact_center_mm()` и
   `render._center_for_info()` учитывают флаг, чтобы не добавлять
   несуществующий подъём мениска к 3D/2D-центру.

Для примера выше теперь получается:

```text
level = 21.477 мм
V     = 2000.00 мм³
flat  = True
```

Это приближение: мениск в переходном режиме не моделируется, но объём,
manifold и горизонтальность соблюдены. Для визуально корректного
мениска в этом режиме нужен солвер из следующего раздела.

## 7. Требования к специальному солверу

- Вход: `matrix_world` трубки, целевой объём, свойства жидкости,
  геометрия дна/галтели.
- Контактная линия: участки на цилиндрической стенке и на дне/галтели.
- Учёт краевого угла и капиллярного подъёма вблизи смешанной границы.
- Непрерывная зависимость объёма от уровня: без разрыва между flat и
  meniscus-ветками.
- Совместимость с текущим API `build_liquid()` и fast-путём (или
  отдельный, более медленный путь для переходной зоны).
- Возврат `flat=False`, если построен настоящий мениск; признак
  смешанного контакта — отдельным полем в `info`, если понадобится.

## 8. Критерии готовности

- 2000 мм³ при 50° строится настоящим мениском со смешанным контактом,
  а не плоским fallback.
- `V(θ) = const` там, где это физически ожидается; для заданного объёма
  уровень находится без скачков.
- `validate_liquid()` проходит: manifold, отсутствие вырожденных граней,
  точный объём; для mixed-меша проверяется положение линии контакта,
  а не горизонтальность верхней кромки.
- `check_liquid.py` включает переходную зону 40–70° и объёмы,
  попадающие в бывший разрыв (в частности, 2000 мм³ при 50°).
- Визуальная проверка: на рендере нет ступеньки/скачка мениска при
  небольшом изменении объёма.
