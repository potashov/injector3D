# Смешанный мениск: рабочий clipped-прототип

**Дата:** 8 ноября 2026
**Статус:** clipped-солвер интегрирован в `build_liquid()`; для режима
«стенка + дно» строится замкнутый меш, `flat=False`, `mixed=True`.
**Файлы:**

- `injector3d/meniscus_mixed.py` — солвер, крышка и замкнутый меш;
- `injector3d/liquid.py` — автоматический выбор mixed-режима;
- `injector3d/create_scene.py` — валидация mixed-меша;
- `check_meniscus_mixed.py` — автономные проверки;
- `reports/meniscus_mixed_solver_design.md` — исходная концепция и расчёты.

---

## 1. Что реализовано

В отдельном модуле реализованы два пути:

1. **`method='clipped'` — рабочий прототип и значение по умолчанию.**
   Берётся осесимметричный профиль Юнга–Лапласа `zeta(r)` из
   `meniscus.solve_meniscus()`, поверхность `phi(r) = L + zeta(r) - zeta(0)`
   обрезается дном:
   `top(r, theta) = max(phi(r), b(r, theta))`.
   В точках, где `phi < b`, жидкости нет; там поверхность совпадает с дном.
   Смешанная контактная линия получается как пересечение
   `phi(r) = b(r, theta)`.

2. **`method='pde'` — экспериментальный 2D-солвер.**
   Решает линейное уравнение Юнга–Лапласа на полярной сетке с
   obstacle-проекцией и Dirichlet/граничным слоем у стенки. Оставлен для
   дальнейшей разработки; по умолчанию не используется, потому что SOR
   сходится медленно, а постановка краевого условия на стенке ещё не
   доведена до физически точной.

`build_liquid()` вызывает `build_mixed_liquid()` только когда целевой
объём действительно попадает в режим «стенка + дно».  В остальных
случаях (полный мениск, плоский клин у дна, перелив) сохраняется старый
путь.  `use_mixed=False` принудительно оставляет старый путь.

## 2. Алгоритм clipped-прототипа

### 2.1. Геометрия

В локальных координатах трубки:

```text
R   = INNER_RADIUS - CLEARANCE = 9.48 мм
z0  = BOTTOM_THICKNESS + CLEARANCE = 1.02 мм
b(r, theta) = t_z + r·(e_x.z·cos theta + e_y.z·sin theta) + a_z·z0
phi(r)      = L + zeta(r) - zeta(0)
```

`e_x`, `e_y`, `a` — столбцы `matrix_world`; `t_z` — мировая z-трансляция
в мм; `a_z > 0`.

### 2.2. Объём

Для каждого азимута `theta` решается одномерная задача о пересечении
`phi(r)` и линейной по `r` функцией `b(r, theta)`.  Затем интеграл

```text
V = (1/a_z) ∫∫ r·max(phi(r) - b(r, theta), 0) dr dtheta
```

считается по точным интервалам смоченности и квадратуре по `r`.  Это
даёт сходимость по углу лучше 0.01 мм³ уже при 256 азимутах; ранняя
2D-полярная квадратура давала систематическую ошибку до ~5 мм³ из-за
разрыва на контактной линии.

### 2.3. Подбор уровня

`V(L)` монотонно возрастает.  Бисекция по `L` в диапазоне
`[bottom_min - 2, spill_level]`, допуск `0.02 мм³`.

### 2.4. Меш

`build_cap_bmesh()` строит верхнюю менисковую крышку на полярной сетке
`120 × 192` в мировых координатах.  В сухих точках `top = b`, поэтому
крышка непрерывна и замыкается по внешней кромке `r = R`.

`build_liquid_bmesh()` строит замкнутый объём: верх, дно и боковые стенки
по границе смоченной области.  Ребро, принадлежащее ровно одной
смоченной ячейке, замыкается боковой гранью; так автоматически
закрываются и внешняя стенка `r = R`, и линия контакта на дне.
`build_liquid_for_target()` после построения уточняет уровень методом
Ньютона по фактическому `bm.calc_volume()`: треугольная сетка и точный
1D-интеграл немного расходятся, а валидация должна сходиться на одной
геометрии.

## 4. Ограничения

1. **Clipped-модель — приближение первого порядка.**
   Поверхность остаётся осесимметричной; 2D-деформация у сухой части
   контактной линии не учитывается.  Краевой угол на дне не задаётся:
   поверхность просто пересекает дно.

2. **Замкнутый меш реализован, но модель остаётся осесимметричной.**
   Верх + дно + стенка замыкаются по границе смоченной области;
   `closed=True` работает.  Точная 2D-форма у сухой части контактной
   линии по-прежнему не решается.

3. **2D-PDE не является рабочим путём.**
   Он оставлен в модуле как эксперимент.  SOR сходится медленно,
   Dirichlet-условие на стенке даёт отличающийся от осесимметричного
   профиль, а Neumann-вариант требует более устойчивого решателя
   (мультигрид/CG) и отдельной проверки краевого угла.

4. **Fast-путь `build_liquid()` для mixed-режима не используется.**
   `_MENISCUS_TEMPLATE_CACHE` рассчитан на полный эллипс; mixed-путь
   каждый раз решает уровень clipped-солвером.  Кэш по ориентации и
   объёму — возможная оптимизация.

5. **Замечание по существующему коду.**
   `meniscus.solve_meniscus()` без явного `contact_angle_deg` падает с
   `NameError: CONTACT_ANGLE_DEG is not defined` (константа не импортирована
   в `meniscus.py`).  Новый модуль всегда передаёт угол явно; текущий код
   не изменялся.

## 6. Интеграция и тестовые рендеры

### 6.1. Выбор режима

`liquid.build_liquid()` сначала вызывает
`meniscus_mixed.build_mixed_liquid()`:

- `mixed=True` — clipped-меш;
- `flat=True` (кромка ниже самого низкого дна) — старый плоский клин;
- `spilled=True` или полный контакт — старый путь полного мениска.

В mixed-режиме `info` содержит `mixed=True`, `method='clipped'`,
`contact_mm`, `bottom_min_mm`, `bottom_max_mm`; `volume_mm3` — фактический
объём замкнутого меша.  `validate_liquid()` для mixed не требует
горизонтальной верхней кромки (сухая часть дна может быть выше кромки),
но проверяет manifold, объём и положение линии контакта.
`contact_level_mm()`/`contact_center_mm()` и метаданные рендера учитывают
`mixed=True`.

### 6.2. `check_liquid.py`, раздел 4b

```text
θ=40°: V=2000.00, mixed=False, flat=False, method=meniscus, level=5.273
θ=50°: V=2000.00, mixed=True,  flat=False, method=clipped,  level=4.086
θ=60°: V=2000.00, mixed=True,  flat=False, method=clipped,  level=2.483
```

Уровни здесь — для `matrix_for` (поворот вокруг нижнего торца), поэтому
они отличаются от `tilt_matrix` с точкой опоры в середине трубки.
`check_meniscus_mixed.py`, `check_liquid_presets.py` и
`check_postprocess.py` проходят.
