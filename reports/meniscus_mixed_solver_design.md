## 1. Задача

В `reports/meniscus_mixed_contact.md` описана ситуация, когда при малом
объёме и большом наклоне плоскость контакта полного мениска касается дна.
Тогда контактная линия перестаёт быть замкнутым эллипсом целиком на
цилиндрической стенке: часть линии лежит на стенке, часть — на дне/галтели.
Текущий `build_liquid()` в этом режиме использует плоский fallback, поэтому
объём сохраняется, но физический мениск не строится.

Нужен отдельный солвер, который:

- принимает `matrix_world` трубки, целевой объём, свойства жидкости и
  геометрию дна;
- строит поверхность со смешанной контактной линией;
- даёт непрерывную зависимость объёма от уровня;
- возвращает замкнутый manifold-меш (или, как минимум, менисковую крышку
  для замены плоского среза);
- может вызываться из существующего проекта как отдельная функция.

## 2. Что проверено в текущем коде

### 2.1. Геометрия и критерий полного мениска

Для наклона 50° и `tilt_matrix(50°, 270°)` получены:

```text
rise            = 3.033755 мм
z_bottom_max    = 24.349516 мм
z_bottom_min    =  9.825313 мм
level*          = 21.315761 мм
spill_level     = 68.290807 мм
```

`level* = z_bottom_max - rise` — граница, на которой плоскость контакта
касается самой высокой точки дна.

Критерий текущего полного мениска:

```text
contact = level + rise
contact > z_bottom_max   — полный эллипс на стенке;
contact <= z_bottom_max  — текущий плоский fallback.
```

### 2.2. Объёмы на границе

Существующий код даёт:

```text
V_flat(level*)          = 1939.641740 мм³
V_meniscus(level* + ε)  = 2237.006619 мм³
```

Скачок между ветками:

```text
2237.01 - 1939.64 ≈ 297.36 мм³
```

В отчёте `meniscus_mixed_contact.md` указано `V_meniscus ≈ 2241.39` и скачок
`≈ 301.75 мм³`; различие объясняется выбором точки `ε` на границе и
чувствительностью к положению плоскости контакта. Порядок и сам факт
разрыва подтверждены.

### 2.3. Независимая проверка плоского объёма

Чтобы исключить ошибку проекции «мир → локальные координаты», плоский
объём при `level*` проверен независимым интегралом в локальной системе
трубки:

```text
R   = 9.48 мм
z0  = 1.02 мм
t_z = 16.431771 мм
a_y = 0.766044497
a_z = 0.642787576
L   = 21.3157609105 мм

верхняя граница по локальному z:
    z_upper(x, y) = (L - t_z - a_y·y) / a_z

V = ∫∫_диск max(z_upper - z0, 0) dx dy
  ≈ 1939.646659 мм³
```

Существующий `volume_at_level()` даёт `1939.641740 мм³`. Расхождение
`≈ 0.005 мм³` — это ошибка дискретизации. **Плоский builder считает объём
корректно**; подозрение на ошибку в нём не подтвердилось.

### 2.4. Текущий fallback

По данным отчёта, для `2000 мм³` при 50° текущий код строит:

```text
level = 21.477 мм
V     = 2000.00 мм³
flat  = True
```

То есть задача сейчас решается геометрически корректным по объёму, но
физически упрощённым плоским горизонтом.

## 3. Физическая постановка для смешанного контакта

### 3.1. Почему локальные цилиндрические координаты

Главная сложность текущей схемы — построение области в мировых `X,Y`:
при наклоне проекция дна и стенки образует эллипсы, а контактная линия
может состоять из дуги на стенке и хорды на дне. В локальных координатах
трубки задача проще:

- трубка — цилиндр `r <= R`, дно — плоскость `z = z0`;
- свободная поверхность задаётся как функция над диском `r <= R`;
- стенка — это всегда `r = R`;
- смешанный контакт получается естественно: часть диска, где поверхность
  выше дна, является жидкостью; граница `φ = b` — контакт с дном,
  а участок `r = R`, где `φ > b`, — контакт со стенкой.

Это позволяет использовать одну постановку для трёх режимов:

1. плоскость ниже дна — жидкости нет;
2. смешанный контакт — часть контактной линии на дне, часть на стенке;
3. полный контакт — вся стенка смочена.

### 3.2. Обозначения

Пусть:

```text
M       — matrix_world трубки;
R3      — M.to_3x3();
t       — M.translation;
e_x     — R3 @ (1,0,0);
e_y     — R3 @ (0,1,0);
a       — R3 @ (0,0,1);   // ось трубки в мире
z0      — локальная высота дна (BOTTOM_THICKNESS + CLEARANCE);
R       — внутренний радиус меша жидкости (INNER_RADIUS - CLEARANCE).
```

Для локальной точки `(r cos θ, r sin θ, z)` мировая высота:

```text
w(r, θ, z) = t_z + r·g(θ) + a_z·z,
g(θ) = e_x.z·cos θ + e_y.z·sin θ.
```

Считаем `a_z > 0` (наклон меньше 90°).

Высота дна в мире:

```text
b(r, θ) = t_z + r·g(θ) + a_z·z0.
```

Свободная поверхность — функция `φ(r, θ)` — мировая высота поверхности.
Локальная высота поверхности:

```text
Z(r, θ) = (φ(r, θ) - t_z - r·g(θ)) / a_z.
```

Жидкость существует там, где `Z > z0`, то есть `φ > b`.

### 3.3. Объём

Элемент объёма в локальных цилиндрических координатах:

```text
dV = r dr dθ dz.
```

Объём жидкости:

```text
V = ∫∫ r · max(Z - z0, 0) dr dθ
  = (1/a_z) ∫∫ r · max(φ - b, 0) dr dθ.
```

Это удобно: объём считается по тому же полярному диску, на котором
решается уравнение, без построения мировой проекции области.

### 3.4. Уравнение Юнга–Лапласа

В мировых горизонтальных координатах:

```text
∇²_world φ = (φ - L) / λ²,
λ² = σ / (ρ g).
```

Здесь `L` — уровень плоской поверхности (давление, при котором кривизна
равна нулю). Для полного мениска текущего проекта `L` — уровень на оси,
а у стенки поверхность выше на `rise`.

Переход из локальных `(x, y)` в мировые горизонтальные координаты —
линейное отображение:

```text
A = [[e_x.x, e_y.x],
     [e_x.y, e_y.y]]
```

Метрика:

```text
G = Aᵀ A.
```

Тогда:

```text
∇²_world φ = G^{ij} ∂_i∂_j φ
```

— эллиптический оператор с постоянными коэффициентами. На полярной сетке
в локальном диске его можно дискретизировать через `∂_r`, `∂_θ` и
коэффициенты метрики.

### 3.5. Граничные условия

#### Стенка `r = R`

Строгое условие краевого угла:

```text
(∇φ · e_r) / sqrt(1 + |∇φ|²) = cos θ_c,
e_r(θ) = e_x cos θ + e_y sin θ.
```

Для прототипа предлагается более простая и устойчивая аппроксимация:

```text
φ(R, θ) = max(L + rise, b(R, θ)).
```

Смысл:

- если стенка смочена (`b(R,θ) < L + rise`), поверхность у стенки стоит на
  высоте полного мениска `L + rise`;
- если в данном θ дно поднялось выше уровня, стенка сухая, и поверхность
  у стенки совпадает с дном `b(R,θ)`;
- в точках перехода обе ветки равны, поэтому граничное условие непрерывно.

Именно это условие естественно даёт смешанную контактную линию: на части
окружности `r=R` поверхность выше дна (контакт со стенкой), на остальной
части — равна дну (контакт с дном).

Альтернатива для следующей итерации — честное Neumann-условие с краевым
углом и итеративным подбором контактной линии. Его имеет смысл вводить
после рабочего прототипа.

#### Дно

Строгое условие на линии `φ = b`:

```text
(-∇φ · a_xy + a_z) / sqrt(1 + |∇φ|²) = cos θ_c.
```

В прототипе предлагается не задавать его явно, а использовать
**obstacle-проекцию**:

```text
φ ← max(φ, b).
```

Тогда поверхность не может опуститься ниже дна, а линия `φ = b` возникает
автоматически. Краевой угол на дне будет приближённым; его нужно проверить
и, при необходимости, добавить поправку/итерацию.

## 4. Предлагаемая концепция солвера

### 4.1. Общая схема

```text
вход: matrix_world, target_volume, liquid_config, геометрия
  │
  ├─ 1. Построить полярную сетку на локальном диске r ∈ [0, R].
  ├─ 2. Для каждой точки вычислить b(r, θ) и граничное φ_wall(θ).
  ├─ 3. Задать начальное φ = L (плоский уровень), спроецировать на b.
  ├─ 4. Решить уравнение Юнга–Лапласа с obstacle-проекцией.
  ├─ 5. Вычислить объём V(L).
  ├─ 6. Бисекцией по L найти V(L) = target_volume.
  ├─ 7. Извлечь контактную линию: стенка + дно.
  ├─ 8. Построить меш поверхности/жидкости.
  └─ 9. Вернуть bmesh + info.
```

### 4.2. Сетка

- Полярная сетка `Nr × Nθ` на локальном диске.
- `Nθ` желательно кратно `REVOLVE_SEGMENTS` (192) или не меньше 192,
  чтобы контактная линия совпадала с сеткой трубки.
- `Nr` — 80–160; для проверки сходимости использовать 40/80/160.
- Центр `r=0` — особая точка. Варианты:
  - отдельная центральная вершина и треугольники к первому кольцу;
  - либо малый внутренний радиус `r_min` и условие симметрии.
- Угол `θ` периодический.

### 4.3. Решатель уравнения

Рекомендуемый поэтапный вариант:

#### Этап A — линейный солвер с obstacle (первый прототип)

```text
G^{ij} ∂_i∂_j φ = (φ - L) / λ²
φ(R, θ) = max(L + rise, b(R, θ))
φ ← max(φ, b)   после каждой итерации
```

Решается итерационно (SOR/Гаусс–Зейдель) или через разреженную линейную
систему. Линейный оператор с постоянными коэффициентами удобен и устойчив.

Плюсы: быстро сходится, легко проверить объём и непрерывность.
Минусы: форма мениска линейная, краевой угол на стенке выполняется
приближённо.

#### Этап B — нелинейный солвер (уточнение)

```text
∇·(∇φ / sqrt(1 + |∇φ|²)) = (φ - L) / λ²
```

Picard-итерации:

1. по текущему `φ` вычислить `K = 1/sqrt(1 + |∇φ|²)`;
2. решить линейную задачу с замороженным `K`;
3. повторить 3–8 раз.

Это даёт более физический профиль и позволяет точнее проверить краевой
угол. Для первого рабочего файла достаточно этапа A; этап B — улучшение.

### 4.4. Подбор уровня под объём

`V(L)` монотонно возрастает: при увеличении `L` растёт и `Z`, и область
жидкости. Поэтому:

```text
L_lo = bottom_min - запас
L_hi = spill_level
```

Бисекция по `L`:

- на каждой итерации решать уравнение;
- считать `V` по формуле из §3.3;
- останавливаться при `|V - target| <= tol` (например, `0.02 мм³`);
- тёплый старт: решение с предыдущего `L` использовать как начальное
  приближение;
- при `target >= V(L_hi)` возвращать `spilled=True`.

### 4.5. Извлечение контактной линии

После решения:

- **Стенка:** точки `r=R`, где `φ(R,θ) > b(R,θ) + tol`.
  Это дуга (или несколько дуг) на стенке.
- **Дно:** линия уровня `φ(r,θ) = b(r,θ)` внутри диска.
  Извлекается marching squares / обходом ячеек, где `φ - b` меняет знак.
- **Точки перехода:** пересечение концов дуги стенки с линией дна.
  В них `φ = b`, поэтому линия непрерывна.

Для меша удобно хранить:

```text
contact_wall: список (θ, φ, x, y, z)
contact_bottom: список (r, θ, x, y, z)
transition_points: 2 точки
```

### 4.6. Построение меша

Есть два уровня результата.

#### Вариант 1 — только менисковая крышка (минимальный интеграционный API)

Возвращается поверхность `z = Z(r,θ)` над областью `φ > b` плюс, при
необходимости, плоская часть `Z=z0` над сухой областью. Такой патч можно
использовать в существующем `build_liquid()` вместо плоского среза.

Это самый простой путь для первого прототипа.

#### Вариант 2 — замкнутый меш жидкости

Строится как цилиндр `r<=R`, ограниченный снизу `z0`, сверху `Z(r,θ)`:

- верхняя поверхность — полярная сетка `(r,θ,Z)`;
- нижняя поверхность — `z0` над смоченной областью;
- боковая стенка — `r=R` от `z0` до `Z(R,θ)`;
- в сухой области `Z=z0`, толщина нулевая; такие ячейки нужно либо
  сваривать, либо не создавать.

Для замкнутого меша обязательно:

```text
bmesh.ops.remove_doubles(...)
bmesh.ops.recalc_face_normals(...)
проверка: все рёбра имеют 2 грани (кроме допустимых краёв, если они есть)
```

Если строить только крышку, требование manifold относится к ней: без
висячих рёбер и вырожденных граней.

## 5. Почему выбран именно такой подход

1. **Локальный диск вместо мировой проекции.**
   В мировых `X,Y` смешанная контактная линия — это эллипс + хорда, а
   область зависит от уровня и наклона. В локальных координатах область
   всегда диск `r<=R`, а смешанность возникает через obstacle `φ>=b`.
   Это резко упрощает и геометрию, и объём.

2. **Одна постановка для flat / mixed / full.**
   Не нужно вводить отдельные ветки «плоско», «полный мениск», «переход».
   Все режимы — это одно уравнение с разными уровнями `L` и obstacle.

3. **Естественная непрерывность объёма.**
   При `L` ниже `bottom_min` жидкости нет; при росте `L` область `φ>b`
   растёт непрерывно; при `L`, когда `b(R,θ) < L+rise` на всей стенке,
   решение переходит в полный мениск. Разрыва между ветками нет.

4. **Простая проверка объёма.**
   Объём — интеграл по тому же диску, где живёт решение. Не нужно
   строить мировую проекцию и считать пересечения эллипсов.

5. **Совместимость с текущими параметрами.**
   `R`, `z0`, `λ`, `rise` берутся из существующих `config.py` и
   `meniscus.py`. `rise` для полного мениска уже проверен и может быть
   использован как граничная высота.

## 6. Механизмы проверки качества

### 6.1. Проверка объёма

- `|V_mesh - target| <= 0.02 мм³` (или `max(0.05, 2e-4·target)`).
- Сравнение интеграла §3.3 с `bm.calc_volume(signed=True)`.
- Баланс: `V_flat(L) + V_meniscus_correction ≈ V_target`.

### 6.2. Проверка предельных режимов

1. **Нет жидкости.**
   `L <= bottom_min` → `V ≈ 0`, меш пустой/None.

2. **Полный мениск.**
   Для `L` выше `z_bottom_max - rise` solution должен переходить в
   полный мениск. Сравнить:
   - `rise` с `meniscus_wall_rise_mm()`;
   - объём с `volume_at_level()` / `meniscus_volume_mm3()`;
   - форму поверхности с текущим `_build_meniscus_bmesh()` (без изменения
     кода, только вызов для сравнения).

3. **Плоский предел.**
   При `rise → 0` или `λ → 0` поверхность должна стремиться к плоскости
   `φ = L`; объём — к `V_flat(L)`.

### 6.3. Непрерывность по уровню/объёму

Sweep по `L` или по `target` в диапазоне, включающем переход:

```text
target = 1800, 1900, 1939.64, 1950, 2000, 2100, 2200, 2237, 2300 мм³
```

Проверки:

- `V(L)` строго возрастает;
- нет скачка `ΔV` больше допуска между соседними точками;
- `max |Δlevel|` при малом `Δtarget` не превышает разумного порога;
- в точке бывшего разрыва (`2000@50°`) решение не переключается на
  `flat=True`.

### 6.4. Проверка краевого угла

На стенке:

```text
cos θ_num = (∇φ · e_r) / sqrt(1 + |∇φ|²)
```

Сравнить с `cos θ_c`:

- для этапа A допуск можно задать `±0.1…0.15` (линейная аппроксимация);
- для этапа B — `±0.02…0.05`.

На дне:

```text
cos θ_num = (-∇φ · a_xy + a_z) / sqrt(1 + |∇φ|²)
```

Если ошибка велика, это сигнал, что obstacle-проекция без Neumann-условия
недостаточна; тогда переходить к этапу B или к итеративному подбору
контактной линии.

### 6.5. Проверка сетки

- `bm.calc_volume(signed=True) > 0`.
- Все рёбра manifold (2 грани), кроме допустимых границ, если это
  открытая крышка.
- Нет вырожденных граней (`area > eps`).
- Нормали согласованы (`recalc_face_normals`).
- Нет самопересечений: проверка знака объёма и визуальная инспекция.
- Вершины на стенке лежат на цилиндре `r=R` с точностью `1e-5`.
- Вершины на дне лежат на `z0` с точностью `1e-5`.

### 6.6. Сходимость по сетке

Для `Nr = 40, 80, 160` и `Nθ = 96, 192, 384`:

- `L` и `V` должны сходиться;
- разница между соседними сетками по `V` — не более `0.05 мм³`;
- форма контактной линии стабилизируется;
- число переходных точек остаётся 2 (для одного смешанного контакта).

### 6.7. Инвариантность к азимуту

При повороте трубки вокруг мировой Z на `φ`:

- объём должен сохраняться;
- форма должна поворачиваться вместе с трубкой;
- `rise` и `level` не должны зависеть от азимута;
- проверка `V(θ) = const` для целевого объёма при разных азимутах.

### 6.8. Визуальная проверка

- Рендер 2000 мм³ при 50° и 60°.
- Нет ступеньки/скачка при переходе между кадрами с малым изменением
  объёма.
- Линия контакта на стенке и дне выглядит непрерывной.
- Мениск не пересекает дно и не выходит за стенку.

## 8. Ограничения и риски

1. **Граничное условие Дирихле vs краевой угол.**
   `φ(R,θ)=max(L+rise,b(R,θ))` обеспечивает непрерывность и хороший объём,
   но не гарантирует точный краевой угол. Это осознанный компромисс
   первого прототипа; проверять `cos θ_num`.

2. **Краевой угол на дне.**
   Obstacle-проекция `φ>=b` не задаёт угол явно. В переходной зоне это
   может дать заметное отклонение. Решение — Neumann-условие + итерация
   контактной линии (этап B).

3. **Центр полярной сетки.**
   В `r=0` сингулярность метрики. Нужна отдельная центральная вершина
   или малый `r_min`; иначе появятся артефакты/деление на ноль.

4. **Стоимость.**
   Бисекция по `L` требует многократного решения PDE. Нужны тёплый старт,
   кэш и умеренная сетка; иначе построение станет дороже рендера.

5. **Меш в сухой области.**
   Если `Z=z0`, верхняя и нижняя поверхности совпадают. Нужно либо
   строить только смоченную часть, либо сваривать вершины и удалять
   вырожденные грани; иначе будет non-manifold.

6. **Совместимость с fast-путём.**
   Текущий `_MENISCUS_TEMPLATE_CACHE` рассчитан на полный эллипс и
   постоянную `ΔV_under`. Для смешанного режима fast-путь неприменим;
   нужен отдельный, более медленный путь только в переходной зоне.

## 10. Итог

- Проблема подтверждена: при 50° и 2000 мм³ целевой объём попадает между
  плоской и полной менисковой ветками.
- Числа текущего кода проверены независимым интегралом; плоский объём
  считается корректно.
- Предложена постановка в локальных цилиндрических координатах: свободная
  поверхность как функция над диском `r<=R`, дно — obstacle `b(r,θ)`,
  стенка — граница `r=R`. Это естественно описывает смешанную контактную
  линию.
- Выбран первый алгоритм: полярная сетка + линейное уравнение
  Юнга–Лапласа с obstacle и граничным условием
  `φ(R,θ)=max(L+rise,b(R,θ))`, бисекция по `L` под целевой объём.
- Определены проверки: объём, предельные режимы, непрерывность,
  краевой угол, manifold, сходимость по сетке, инвариантность к азимуту.
