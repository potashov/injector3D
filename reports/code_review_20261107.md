# Ревизия кода injector3D — 7 ноября 2026

## 1. Общая оценка

**Объём:** 4167 строк Python (≈1310 core-пакет `injector3d/` + ≈2857 внешних скриптов).
**Архитектура:** чистое разделение ответственности — 8 модулей пакета + 10 скриптов верхнего уровня. Нет циклических импортов, нет глобального состояния вне Blender.

### Оценка архитектуры — 9/10

**Сильные стороны:**
- Модульная композиция: `create_scene.py` — точка входа, собирающая модули в конвейер; каждый модуль тестируется отдельно (`check_liquid.py`, `check_liquid_presets.py`, `check_postprocess.py`).
- Метрическая корректность: глобальная константа `MM = 0.001` переводит все размеры из мм в Blender-юниты в одном месте.
- Кэширование мениска (`_MENISCUS_CACHE`, `_MENISCUS_TEMPLATE_CACHE`) — решающая проблема пересборки межа на каждой итерации бисекции.
- Worker-процесс постобработки (`subprocess.Popen` с stdin) — правильный паттерн для долгоживущей обработки.
- Шардирование (`render_parallel.py`) — корректное распределение: master и manifest получают суффиксы, финальные PNG — нет.

**Слабые стороны:**
- `sys.path.insert(0, ...)` в каждом внешнем скрипте — копипаста.
- Нет typecheck, линтера, тестового фреймворка — проверка = ручной запуск assert-скриптов.

## 2. Модульный анализ

### `config.py` (335 строк)

**Качество — 8.5/10**

| Аспект | Оценка |
|--------|--------|
| Документированность | Отлично: каждый параметр прокомментирован с физическим обоснованием |
| Функциональность | `get_liquid_config()` и `get_camera_config()` — правильная паттерн-функция с `**overrides` |
| Поддержание | `LIQUID_PRESETS` легко расширяемы; `TILT_VARIANTS` и `tilt_ring_variants()` покрывают оба режима |

**Замечания:**

1. **`RENDER_SAMPLES = 128` — мёртвый код.** Константа импортировалась в `scene.py` и использовалась только как fallback: `sc.cycles.samples = p.get('samples', RENDER_SAMPLES)`. Поскольку `camera_config` всегда передаётся с полем `'samples'`, этот fallback никогда не срабатывал. **Удалено.**

2. **`LIGHTS` кортеж хранил `_angle`, который нигде не использовался.** В `scene.py` строка `for name, loc, energy, size, _angle in LIGHTS:` показывала мёртвый параметр от черновика. Удалён, формат кортежа упрощён до `(имя, позиция, мощность, размер)`.

### `tube_geometry.py` (185 строк)

**Качество — 9/10**

- Алгоритм «профиль × вращение» со схлопыванием вершин на оси — эталонный подход для 100% manifold-межа.
- `_build_profile()` детально прокомментирован по 10 сегментам.

**Замечания:**

3. **`bmesh.ops.remove_doubles(bm, verts=bm.verts, dist=1e-9)`** — `dist=1e-9` эквивалентно 1e-6 мм. При работе с геометрией, где уже есть проверка `1e-9` для осевых точек, это потенциально избыточная операция на 39×192 = 7488 вершинах. Не ошибка, но стоит пересмотреть.

### `liquid.py` (568 строк)

**Качество — 9.5/10**

Это ядро проекта. Физическая корректность и инженерная глубина впечатляют.

| Аспект | Оценка |
|--------|--------|
| Физика | Юнг-Лаплас решён через RK4 + бисекция, а не эмпирически |
| Оптимизация | `_MENISCUS_TEMPLATE_CACHE` — постоянная поправка ΔV_under |
| Переходы | Плоский fallback у дна и при переливе — корректная обработка edge-кейсов |
| Инвариантность | V(θ) = const проверена на всех углах в `check_liquid.py` |

**Замечания:**

4. **`_normalize_liquid_props()`** принимает `None`, `tuple` и `dict` — правильный полиморфизм, но при передаче `list` или строки упадёт с `AttributeError` в `dict`-ветке.

5. **`_build_meniscus_bmesh()`** — самая сложная функция в файле (120 строк). Создает радиальную сетку (80 колец) поверх эллиптической кромки. Логика верна, но:
   - Формула `center_local_z = (contact_m - mw[2][3]) / mw[2][2]` была без комментариев — это пересечение оси трубки с плоскостью контакта. **Добавлены комментарии.**
   - Код вынесен в отдельную функцию `_meniscus_rings()` для читаемости.

6. **`fast_volume_at_level()`** использует `fast=True` по умолчанию в `build_liquid()`. `tol_mm3=0.02` — это 0.00015% при объёме ~13000 мм³. Избыточно для рендера, где шум Cycles гораздо больше.

7. **`_MENISCUS_TEMPLATE_CACHE` не очищается.** При смене пресета жидкости кэш всё ещё может содержать старые шаблоны. Но `_template_key` включает `props`, поэтому коллизий нет.

### `meniscus.py` (213 строк)

**Качество — 9.5/10**

- Консервативная формулировка через F(r) = r·ζ′/√(1+ζ′²) — правильное решение проблемы сингулярности 1/r.
- RK4 с шагом r_end/nsteps — стандарт. 2000 шагов на R=9.5 мм — h ≈ 0.005 мм, избыточная точность.

**Замечания:**

8. **`ANALYTIC_DELTA_V_MM3` — мёртвый код.** Вычислялся как `2 * math.pi * CAP_LAMBDA_MM ** 2 * INNER_RADIUS * COS`, но нигде не использовался. Аналитический объём считается внутри `solve_meniscus()` и возвращается в результатах. **Удалено.**

9. **`CTG` и `COS` — мёртвые константы.** Вычислялись из `CONTACT_ANGLE` (дефолт воды), но не использовались. Вычисления `ctg` и `cos` теперь происходят внутри `solve_meniscus()` для каждого вызова. **Удалено.**

10. **`theta_deg = max(0.5, min(89.5, theta_deg))`** — защита от деления на ноль и отрицательного угла. Корректно, но `0.5°` — это уже сильное смачивание.

### `materials.py` (93 строки)

**Качество — 8.5/10**

- Чистый, понятный код. Два материала, каждый — через node tree.

**Замечания:**

11. **Fresnel-настройки Principled BSDF не оптимизированы.** В Blender 5.2.3 сокет называется `Specular IOR Level`, не `Specular`. Значения зафиксированы явно: `Specular IOR Level = 0.5` (стандартная шкала F0 от IOR), `Specular Tint = (1,1,1,1)` (нейтральный). **Добавлено.**

### `scene.py` (222 строки)

**Качество — 8.5/10**

- `setup_render_devices()` — корректная фильтрация CUDA-устройств по `GPU_DEVICE_FILTER`.
- `attach_camera_to_tube()` — правильный паттерн: камера становится дочерней.
- `_safe_set()` — правильный fallback для headless-сборок Blender.

**Замечания:**

12. **`addon_utils.enable('cycles', default_set=True)`** — включал аддон каждый раз, даже если он уже активен (шум предупреждениями). **Добавлена проверка.**

13. **`sc.render.use_persistent_data = True`** — ключевая оптимизация для серии рендеров. Может привести к утечкам памяти при длительной работе.

### `render.py` (617 строк)

**Качество — 9/10**

- `_configure_compositor()` — корректная ветка API для Blender 4.3 и 5.x.
- `_lensdistort_raw_px()` — формула дисторсии, выведенная из Blender-шейдера, верифицированная на калибровочной сетке (расхождение ≤ 1.2 px).
- Worker-процесс постобработки — корректная реализация с `subprocess.Popen`.

**Замечания:**

14. **`_render_one()`** — при выключенной постобработке (`opts['enabled'] = False`) кадр рендерится напрямую в финальный путь, но **подписи/маркеры пропускаются** с предупреждением. Правильно, но пользователь может не понять почему.

15. **Временные файлы (JSON метаданных, raw-кадры)** — каждый удалялся по месту создания, но при прерывании прогона (Ctrl+C, ошибка) оставались в `/tmp`. **Добавлен `atexit`-реестр и колбэк `_cleanup_temps()`, регистрирующий все `mkstemp`-файлы.**

### `output_manager.py` (81 строка)

**Качество — 9/10**

- Чистый, без побочных эффектов модуль.
- `_join()` аккуратно убирает лишние подчёркивания.

### `create_scene.py` (600 строк)

**Качество — 8.5/10**

- `main()` — длинная функция, но логически разделена на 6 шагов.
- CLI-парсинг — ручной, без `argparse`. Осознанный выбор: Blender режет argv на `--`, и `argparse` не умеет работать с `--background --python script.py -- --arg1 value1`.

**Замечания:**

16. **`main()` — 600 строк.** Делает слишком много: парсинг CLI, валидация, создание сцены, жидкости, материалов, рендер, экспорт GLB. **Выделена функция `_parse_cli(tail)` с документацией и type-hint возвращаемого значения. `main()` теперь — обёртка, собирающая параметры из словаря.**
