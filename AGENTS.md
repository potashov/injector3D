# AGENTS.md — injector3D

> Каноническая инструкция для AI-агентов. Читается первым. Содержит
> правила работы, команды, инварианты и карту остальной документации.

## 1. Карта документов и правила памяти

| Файл | Что хранит | Когда читать | Когда обновлять |
|---|---|---|---|
| `AGENTS.md` | правила, команды, инварианты, карта документов | всегда | при изменении правил, команд или инвариантов |
| `README.md` | вход для человека, быстрый старт, схема архитектуры | при онбординге и изменении архитектуры | при изменении пользовательского поведения или схемы |
| `PLAN.md` | **только** запланированные и текущие работы | при выборе следующей задачи | при появлении задачи; при завершении задача удаляется |
| `CHANGELOG.md` | краткая история уже сделанных изменений | перед коммитом и при восстановлении контекста | при каждом заметном изменении |
| `reports/README.md` | индекс актуальных отчётов и архива | при поиске подробностей | при добавлении/переносе отчёта |
| `reports/*.md` | подробные отчёты, замеры, обоснования | точечно, по ссылке | при появлении новых деталей |
| `reports/archive/` | исторические планы, аудиты и снимки | только если нужна история | при переносе устаревшего документа |
| `docs/adr/` | ключевые архитектурные решения и их причины | при изменении архитектуры | при принятии/замене решения |
| `injector3d/config.py` | фактические параметры, размеры и пресеты | при любом вопросе о числах | при изменении параметров |
| `check_*.py` | зафиксированные инварианты и ожидаемое поведение | перед правкой и после неё | при изменении инвариантов |

Правила жизненного цикла:

1. **`PLAN.md` — только будущее и текущая работа.** Выполненный пункт
   удаляется, а не помечается галочкой. Краткий факт — в
   `CHANGELOG.md`, подробности — в `reports/`.
2. **`CHANGELOG.md` — только прошлое.** Новые записи — в
   `[Unreleased]`, старые не переписываются; ссылка на коммит/отчёт.
3. **`README.md`** — стабильное описание без статусов; **`AGENTS.md`** —
   правила и команды; **`reports/archive/`** — история, не источник
   текущего статуса.
4. **`docs/adr/`** — архитектурные решения; старый ADR получает статус
   `заменено` или `устарело`.

При изменении кода в том же изменении обнови `check_*.py`,
`CHANGELOG.md` (`[Unreleased]`), `README.md`/`docs/adr/` при изменении
архитектуры, `AGENTS.md` при изменении правил; после завершения удали
пункт из `PLAN.md`; сложные детали добавь в `reports/`.

## 2. Источники истины и порядок чтения

Приоритет информации:

1. `injector3d/config.py` — фактические параметры и размеры.
2. Исполняемый код в `injector3d/` и корневые launcher-скрипты.
3. `check_*.py` — зафиксированные инварианты.
4. `AGENTS.md`, `README.md`, `docs/adr/` — правила, схема и решения.
5. `PLAN.md`, `CHANGELOG.md`, `reports/*` — планы, история и
   обоснования; могут содержать устаревшие статусы.

Порядок чтения: `AGENTS.md` → `config.py` → целевой модуль → ближайший
`check_*.py` → `README.md#архитектура`, `reports/README.md` или
`docs/adr/` при необходимости. `reports/archive/` — исторический слой,
не источник текущего статуса; актуальный план — `PLAN.md`.

## 3. Команды

Локальная сборка Blender лежит в `.gitignore`; используйте её, а не
системный `blender`:

```bash
BL=./blender-5.2.3-linux-x64/blender
$BL --version
```

Основные команды:

```bash
# Серия N+1: вертикаль + N азимутов наклона
$BL --background --python injector3d/create_scene.py -- \
    --mode ring --tilt-count 8 --tilt-angle 10

# Референсный кадр 06120
$BL --background --python render_reference.py

# Проверки жидкости и физики пресетов
$BL --background --python check_liquid.py
$BL --background --python check_liquid_presets.py
$BL --background --python check_meniscus_mixed.py

# Градуировка на стекле (шкала объёма)
$BL --background --python check_graduation.py

# Проверки без Blender (системный python3, PIL/numpy)
python3 check_postprocess.py
python3 check_batch.py
python3 check_timing.py

# Сводка таймингов
python3 summarize_timings.py output/<прогон>/water_manifest.json

# Параллельный и пакетный рендер (системный python3)
python3 render_parallel.py --tilt-count 8 --tilt-angle 10 --gpus 0,1
python3 render_batch.py --liquids water,glycerol \
    --volumes 2000,5000 --tilt-angles 10,20 --gpus 0,1

# Диагностика CUDA/GPU
$BL --background --python check_cuda.py
$BL --background --python check_build_cuda.py
$BL --background --python gpu_info.py
```

Полный набор флагов `create_scene.py` — `reports/step6_cli.md`; имена
файлов — `injector3d/output_manager.py`.

## 4. Инварианты и запреты

### Жидкость

- Меш жидкости строится в **мировых координатах**, а не в локальных
  координатах трубки.
- Объект жидкости **не** является дочерним трубке: иначе при наклоне
  наклонялся бы уровень.
- Уровень подбирается по целевому объёму; инвариант `V(θ) = const`;
  при `V=0` меш жидкости не строится, рендер пустого цилиндра разрешён.
- Свободная поверхность горизонтальна в мировых координатах; при
  наклоне эллиптическая только кромка контакта.
- В ring-режиме два независимых меша: `liquid_upright` и
  `liquid_tilted`; наклонный строится при `φ=0`, затем поворачивается
  вокруг мировой Z.
- Зазор `CLEARANCE = 0.02 мм` предотвращает z-fighting.
- Верх трубки открыт: boundary-рёбра допустимы только на верхней кромке.

### Градуировка

- Позиции рисок считаются из геометрии трубки
  (`h = V/(π·R_внутр²)`), а не снимаются с референса; капиллярный
  подъём в шкале не учитывается.
- Нуль шкалы — внутренняя плоскость дна (`BOTTOM_THICKNESS`).
- Разметка — дочерние трубке объекты (уезжает вместе со стеклом при
  наклоне), а не объекты в мировых координатах, как жидкость.
- Подписи перевёрнуты на 180° и не зеркальны; ориентация вычисляется
  (`wrap_handedness()`), а не задаётся знаком намотки.
- Глифы тесселируются перед намоткой: плоская грань проваливается под
  стекло на большом угле.
- По умолчанию разметка выключена (`SCENE_GRADUATION['enabled']`,
  флаг `--graduation`); цвет, шрифт и кегль меняются только в конфиге.

### Камера и наклон

- Камера жёстко привязана к трубке через `attach_camera_to_tube()`.
- В цикле рендера меняется `tube.matrix_world`, а не камера вручную.
- Свет остаётся в мировых координатах.
- Наклон ring-режима:
  `R(φ) = Rz(φ) · Ry(θ) · Rz(φ)⁻¹` вокруг `TILT_PIVOT_Z_MM`.
- Исторический `AzimuthRig` давал одинаковые кадры; не возвращайте его.

### Постобработка и вывод

- По умолчанию постобработка включена; `--no-postprocess` сохраняет PNG
  сразу и не рисует overlay.
- `postprocess_reference.py --worker` — один процесс на серию; raw PNG
  отправляется в stdin сразу после рендера.
- Bbox считается по alpha-маске raw и пересчитывается в final как
  `x+shift`, `y·scale` с обрезкой по границам.
- Overlay не должен попадать в alpha-bbox.
- Manifest кадра содержит raw/final 2D-центр и bbox-поля:
  `bbox_raw_px`, `bbox_final_px`, `bbox_center_px`, `bbox_width_px`,
  `bbox_height_px`, `bbox_alpha_threshold`, `bbox_touches_border`,
  `bbox_source`.
- PNG в `output/` отслеживается git; `.blend`, `.blend1`, `.json`,
  `.log`, `.glb` в `output/` игнорируются.
- Не удаляйте чужие рендеры и не считайте `output/` временным каталогом.
- Новые прогоны — в новый каталог, без перезаписи старых.

### Общие запреты

- Не используйте системный `blender`, если доступна локальная сборка.
- Не смешивайте миллиметры и метры: в конфиге миллиметры, в Blender —
  через `MM = 0.001`.
- Не меняйте геометрию, материалы, оптику или физику «попутно».
- Не коммитьте без явной просьбы.
- Не добавляйте в коммит `.blend`, `.json`, `.log`, `.glb` из `output/`.

## 5. Архитектура и решения

Актуальная схема и поток — `README.md#архитектура`. Кратко:
`create_scene.py` собирает сцену, строит трубку и жидкость, применяет
материалы и вызывает `render.py`; `render_parallel.py` и
`render_batch.py` — launcher-скрипты; постобработка идёт через
`postprocess_reference.py --worker`.

Причины ключевых решений — `docs/adr/`; подробности —
`reports/README.md`, `reports/step*.md`, `reports/meniscus_mixed_*.md`,
`reports/performance.md`, `reports/timing_instrumentation.md`.
